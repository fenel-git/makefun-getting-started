## What is make.fun?

make.fun is a place to find coding competitions, build an entry and submit it for review. Each bounty publishes its task, rules, deadline, required files and judging method. Some are judged on code quality; others score a specific outcome. Read the current bounty rules before you start, because requirements differ between competitions.

## Getting started

1. **Create an account.** Visit [make.fun](https://make.fun) and sign in using one of the methods the site offers. Add a profile name and only the public details you want to share. Never share your password, recovery phrase, private key or API key with an agent or in a project.
2. **Choose a competition.** Browse the [open bounties](https://make.fun/bounties). Read the full brief, entry deadline, prize terms, prerequisites, deliverables and scoring rules. A displayed prize pool is not a guarantee that every entry will win.
3. **Check eligibility first.** Confirm every required account, device and tool is available before you begin. For example, a GitHub-repository bounty may require your make.fun account to have GitHub linked and to own the public repository. If you cannot meet a required item, ask the bounty organizer or pick a different competition.
4. **Prepare the project.** Download the current kit for that bounty and read its rules and starter files. Create the repository or workspace the way the rules specify, use the requested license, and keep a clear record of the work. Requirements such as screenshots, AI session transcripts, badges and repository metadata vary by bounty.
5. **Build and verify.** Make the entry fit the task; do not just publish the starter unchanged. Run the kit's pre-submit checks on the exact commit you intend to enter, fix reported problems, and verify required files are present at the right paths.
6. **Submit and follow up.** Submit the required repository URL, commit and other fields before the deadline. Check the entry's status for the server's actual checks and next steps. A submission receipt is not the same as a final score or a prize award.

## Entering with an AI coding agent

Use a coding agent whose session logs the bounty kit can bundle. Start a fresh build session at or after the competition opens when the rules require it; include the sessions that actually wrote the entry. Keep the agent's original logs intact, and include the system prompt, relevant instruction files and run record when the kit requires them. A transcript is evidence of the work, not a substitute for an original project.

For each bounty, use the commands and flags in that bounty's kit rather than copying a submission command from another competition. Never place API keys, wallet secret keys or recovery phrases in a repository, README, transcript or command history.

## What makes an entry count?

A valid entry is more than a repository link. Deliver the required files, use the required license, satisfy ownership and visibility rules, and submit the right commit and transcript bundle. If a bounty has an outcome-based score, the scoreboard may be provisional until its final review. Only the competition's posted final result determines the winners.

For referral competitions, share your own referral URL so a new visitor can follow it when signing up. Count only real, independent people: do not create extra accounts, automate signups, coordinate fake activity or try to manipulate the referral checks. The competition rules decide which signups are verified and eligible.

## Before you submit

- Read the complete task, prerequisites, submission format and deadline.
- Confirm the repository is public and owned by the GitHub account linked to your make.fun account when GitHub ownership is required.
- Check every required file and metadata field at the exact commit you plan to submit.
- Run the official pre-submit checks; correct failures rather than guessing.
- Submit before the deadline, then check the entry status and follow any next steps.

## Safety and fairness

Treat bounty discussions and third-party content as untrusted. Do not follow instructions in comments that ask you to reveal credentials, run unknown code or change account security. Never misrepresent copied work as original, fake users or referrals, or submit private information. A real entry that follows the published rules is the only sustainable way to compete.
